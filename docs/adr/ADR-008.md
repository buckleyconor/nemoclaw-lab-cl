# ADR-008: MonitoringAdapter interface — agent is vertical-blind

**Status:** Accepted

## Decision

The MCP `monitor` and `logs` tools delegate to a `MonitoringAdapter` interface with two implementations: `RedfishAdapter` (for server/datacenter verticals) and `GenericAdapter` (for all other verticals). The agent loop, skills, and soul.md are written against the abstract interface and are unaware of the underlying protocol.

## Context

The flagship vertical (AI Infrastructure) uses Redfish — the DMTF standard for out-of-band server management. Future verticals (laptop fleet, oil-gas, healthcare) use proprietary or generic telemetry streams. The agent needs to treat all of these identically: poll for events, retrieve log bundles, report asset health.

The adapter pattern was chosen over:
- **Vertical-specific MCP tool implementations** — would require different agent skills per vertical, breaking the "content not code" principle (ADR-007).
- **A single generic adapter** — Redfish has specific semantics (event IDs, severity levels, Lifecycle Log structure) that a generic adapter would misrepresent.

The `monitoring_adapter` field in `pack.yaml` selects which adapter is loaded at startup.

## Consequences

**Positive:**
- Agent skills and loop code are vertical-blind — they call `monitor_list_events()` and `logs_get_bundle()` regardless of vertical.
- Adding a new protocol (e.g., SNMP, OPC-UA) requires only a new `MonitoringAdapter` subclass, not changes to the agent or existing services.
- `RedfishAdapter` can be hardened for real Redfish endpoints in a future production phase without touching the agent.

**Negative:**
- The adapter interface must be kept minimal enough to work across all protocols. Redfish-specific metadata (e.g., `MessageId`, `OriginOfCondition`) is not surfaced to the agent.
- Verticals using the `GenericAdapter` lose Redfish-specific log structure — the log bundle is a flat text file rather than structured JSON. This is acceptable for demo purposes.
- A new protocol vertical requires a developer to write an adapter; pack authors cannot do this alone.
