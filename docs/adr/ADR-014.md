# ADR-014: Single-VM production target with the shared lab inference endpoint

**Status:** Accepted

## Decision

The production deployment target is a single Ubuntu 24.04 x86_64 VM (docker +
git preinstalled) running the docker-compose stack, the agent sandbox and the
host daemons — everything except the LLM, which is the lab's **shared
inference endpoint** (OpenAI-compatible with tool calling, private/internal
address, real API key required). Four mechanics follow:

1. **Host inference proxy is the standard sandbox→LLM route.** A host nginx
   listener (default `:18100`, `deploy/scripts/run-inference-proxy.sh`)
   forwards `http://host.openshell.internal:18100/v1/...` to
   `$LLM_BASE_URL/...`. The sandbox is onboarded against the proxy URL, never
   the raw endpoint (`LLM_DIRECT=1` opts out for a genuinely public endpoint).
2. **`LLM_API_KEY` is required** — the dummy `vllm` default is gone from
   `onboard-openclaw.sh` and `.env.example`, and bootstrap/doctor probe the
   endpoint *authenticated* so a rejected key is distinguishable from an
   unreachable host.
3. **Repoint without re-onboard**: `make repoint-llm`
   (`deploy/scripts/repoint-llm.sh`) re-renders the proxy for a new
   `LLM_BASE_URL` and syncs model/key into the live sandbox via
   `nemoclaw inference set`, verifying by reading the model back out of the
   sandbox's `openclaw.json`. Full re-onboard (`make bootstrap FORCE=1`)
   remains the reset path. `make doctor` flags `.env`-vs-sandbox model drift.
4. **No arch assumption**: the Makefile detects `PLATFORM` from `uname -m`
   (the compose path always built natively); the compose subnet is pinned to
   `172.28.100.0/24` so printed ufw rules are deterministic.

## Context

The previous production target was Charmed K8s (ADR and Helm chart remain in
the tree — the k8s path is unchanged and dormant on a single VM: doctor's
lab-proxy checks self-disable when `LAB_INGRESS_HOST` is unset).

ADR-003 already declared the LLM an external, swappable endpoint, but decided
none of the mechanics a *shared, private, authenticated* endpoint forces:

- **The SSRF guard**: `nemoclaw onboard`/`inference set` refuse endpoints
  resolving to private addresses. The `host.openshell.internal` alias is
  exempt for inference (proven on the reference GB10 host: onboarding against
  the alias passed with no bypass flags), unlike for MCP where the alias is
  rejected by design (docs/TROUBLESHOOTING.md).
- **Policy guard #6073**: NemoClaw network-policy presets may only pin
  `host.openshell.internal` — a direct route to the private endpoint could
  not be given an egress rule even if registration succeeded. The proxy is
  therefore the supported route, not a workaround.
- **Bake-in at onboard**: the endpoint URL is written into the sandbox once.
  Baking the *proxy's* stable URL instead of the raw endpoint turns "the lab
  repointed the model" into a host-side nginx re-render plus one
  `inference set` — seconds, not a sandbox image rebuild.
- Endpoint models change over time, so repointing is a routine operation, not
  a rebuild-worthy event.

## Consequences

**Positive:**
- One `.env` block (`LLM_BASE_URL`/`LLM_MODEL`/`LLM_API_KEY`) drives
  everything; `make repoint-llm` applies changes to a live agent in seconds.
- The sandbox-facing URL never changes, so network policy, onboarding and
  repointing all agree on `host.openshell.internal:18100`.
- Works identically on the GB10 dev box (which pioneered the :18100 proxy
  pattern) and the production VM.

**Negative:**
- nginx becomes a host dependency on the VM (accepted: proven pattern, shared
  with the k8s lab proxy `run-lab-proxy.sh`, TLS-capable via `LLM_CA`).
- Endpoint drift is not detectable from the sandbox config (it stores a
  routed placeholder base URL); doctor covers that hop by probing through the
  proxy instead. Model drift *is* detected (openclaw.json read-back).
- Whether `inference set` re-persists a *changed* API key value is unproven;
  if it does not, key rotation falls back to `make bootstrap FORCE=1`
  (repoint-llm prints this).
