# ADR-009: Semantic KB search (fastembed ONNX + FAISS-cpu) with word-match fallback

**Status:** Accepted

## Decision

KB article search uses a two-pass approach:
1. **Semantic search** — error signature is embedded with `fastembed` (BAAI/bge-small-en-v1.5, ONNX, CPU) and compared against a FAISS flat-index of pre-embedded KB article titles and summaries. Returns the top-1 match with a cosine similarity score expressed as a percentage confidence.
2. **Word-match fallback** — if semantic confidence falls below a threshold, a TF-IDF-style keyword overlap check is run against article titles. Used for signatures where the LLM output drifts from the canonical phrasing.

Both search paths are run against the local pack KB (`packs/{id}/kb/*.md`). There is no external search call.

## Context

Three KB search approaches were considered:

- **Exact string match** — fast and deterministic, but the LLM's extracted signature rarely matches KB titles exactly (capitalisation, word order, extra context).
- **LLM re-ranking** — feed all KB article titles to the LLM and ask it to rank. Adds latency (extra LLM call) and is non-deterministic.
- **Embedding similarity + fallback** ✅ — fast at query time (FAISS lookup is sub-millisecond), works on CPU, handles paraphrase and abbreviation ("Xid 79" matches "NVIDIA GPU Xid Error 79" with 74% confidence), and can be used without network access.

fastembed was chosen over sentence-transformers because it ships as a pure ONNX model with no PyTorch dependency, keeping the image small and compatible with arm64.

## Consequences

**Positive:**
- KB search is fully offline — no external API call at query time.
- FAISS index is built once per process start from the pack's KB articles; subsequent queries are sub-millisecond.
- The two-pass design ensures a match is always found for in-pack scenarios (semantic may miss; word-match catches exact title words).
- Confidence score is surfaced to the Operator Dashboard so participants can see how certain the match is.

**Negative:**
- Index is rebuilt on every service restart (no persistence). For large KB collections (100+ articles) this adds ~5 s startup time.
- fastembed's bge-small-en-v1.5 model is a 384-dim general encoder — not fine-tuned for IT/hardware terminology. Domain-specific tuning would improve confidence scores.
- Word-match fallback can produce false positives if two KB articles share common technical terms.
