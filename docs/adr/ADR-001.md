# ADR-001: Custom minimal Redfish mock instead of sushy-tools / DMTF mockup server

**Status:** Accepted

## Decision

Build a purpose-built `services/simulator/` FastAPI service rather than deploying sushy-tools or the DMTF mockup server.

## Context

The demo requires a simulated Dell PowerEdge server (and analogous devices for other verticals) that emits fault events on demand and returns pre-authored log bundles. Two off-the-shelf options were evaluated:

- **sushy-tools** — a full Redfish emulator backed by libvirt/VirtualBox. Requires a hypervisor, is stateful across reboots, and its API surface is far wider than needed.
- **DMTF mockup server** — serves static JSON from filesystem fixtures. Read-only; cannot inject events or change state at runtime.

Neither option supports the core requirement: *inject a specific scenario fault on presenter command, have the simulator return faulted logs for that scenario, then return to healthy state on reset*.

## Consequences

**Positive:**
- Simulator surface is minimal — only the endpoints the MCP `monitor` and `logs` tools actually call.
- Scenario injection, log bundle lookup, and health state are first-class operations via `POST /api/run/{scenario_id}` and `POST /api/reset`.
- The `MonitoringAdapter` interface (`services/mcp_tools/adapters/`) abstracts Redfish vs. generic protocols, so non-Redfish verticals (laptop-fleet, oil-gas) use the same agent loop with a different adapter.
- Runs on any platform (macOS dev, Linux CI, arm64 GB10) with no hypervisor.

**Negative:**
- Redfish fidelity is limited to the event schema subset we emit. Not a drop-in for testing real Redfish clients.
- Each new vertical may need a new adapter if it uses a protocol not yet covered by `GenericAdapter`.
