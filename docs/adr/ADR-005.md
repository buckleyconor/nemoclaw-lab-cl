# ADR-005: In-app React dashboard for HITL — Teams/Slack deferred

**Status:** Accepted

## Decision

The operator-facing Approve/Deny interface is built into the React dashboard (served at port 8001), not routed through Microsoft Teams, Slack, or an email notification system. Notification integrations are deferred.

## Context

The lab demo needs an operator decision UI that is immediately visible during a live presentation. Several delivery channels were considered:

- **Teams/Slack adaptive cards** — realistic enterprise pattern but requires OAuth app registration, outbound webhook infrastructure, and a publicly accessible callback URL. Impractical for a self-contained lab demo.
- **Email approval links** — same infrastructure problem; token delivery is asynchronous and the demo pacing suffers.
- **Dedicated approval page (out-of-app)** — splits audience attention between two browser tabs.
- **In-app Operator Dashboard** ✅ — the Approve/Deny buttons appear in the same browser window as the Agent Activity feed. The audience sees the agent reasoning and the human decision side by side, which is the core narrative of the demo.

The in-app design also enables the live SSE-driven update model: the Operator Dashboard populates in real time as the agent fills it with signature, KB match, analysis, and remediation steps — no page refresh.

## Consequences

**Positive:**
- Zero external infrastructure required — works in air-gapped environments.
- The decision is made in the same context the audience is watching, reinforcing the HITL story.
- SSE updates mean the audience sees the Operator Dashboard fill up progressively as the agent works.
- The React component is easy to style and extend per vertical.

**Negative:**
- Does not demonstrate the enterprise notification patterns customers would actually use (Teams/Slack).
- A single browser session controls the approval gate — not multi-user by default.
- Future work: add a `POST /api/faults/{id}/decision` webhook consumer so Teams/Slack approval cards can call the same endpoint.
