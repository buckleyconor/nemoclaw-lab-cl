# ADR-002: Canned rotated scenarios with deterministic KB lookup

**Status:** Accepted

## Decision

Each domain pack ships a fixed set of authored scenarios (`scenarios/*.yaml`). The orchestrator rotates through them on each `POST /api/run` call. KB search is semantic-first with a confidence fallback, but the KB articles are pre-authored to contain all scenario signatures — so a match is always found.

## Context

Two design axes were debated:

1. **Scenario generation vs. canned scenarios.** Generating fault events from an LLM at demo time would be more varied but unpredictable — wrong signatures, missing KB matches, or hallucinated log entries could derail a live demo. Canned scenarios authored by SMEs guarantee a clean end-to-end flow.

2. **Live KB retrieval vs. pre-indexed local KB.** Retrieving real Dell KB articles at demo time requires internet access and risks broken links or rate limits. A bundled, indexed KB (`packs/{id}/kb/*.md`) ensures the demo works air-gapped.

The combination means every fault injection produces a guaranteed detection → diagnosis → KB match → operator decision flow, which is the point of the demo. Realism is traded for reliability.

## Consequences

**Positive:**
- Demo flow is deterministic and rehearsable.
- Works fully air-gapped (no external network required after image build).
- SMEs can curate KB articles to highlight Dell-specific remediation detail.
- Scenario rotation means repeated injections show different fault types without presenter intervention.

**Negative:**
- The KB and scenarios can go stale if the real Dell KB diverges from the bundled articles.
- Adding a new vertical requires authoring scenarios and KB articles — there is no auto-generation path.
- The rotation order is predictable; a knowledgeable audience could anticipate the next fault type.
