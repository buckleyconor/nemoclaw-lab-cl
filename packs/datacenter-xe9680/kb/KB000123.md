# GPU Xid 79: GPU Has Fallen Off the Bus — Detection and Remediation

> **PLACEHOLDER** — SME: replace body with the real Dell KB article for Xid 79 on XE9680 / H100 SXM5.

## Summary

Xid 79 indicates that the GPU has become unresponsive and the NVIDIA driver has lost PCI Express communication with the device. The GPU effectively "falls off the bus" — it no longer responds to memory reads or configuration cycles. This is a critical fault requiring immediate node remediation.

## Affected products

- Dell PowerEdge XE9680 with NVIDIA H100 SXM5 80 GB GPUs
- NVIDIA driver 525.x – 535.x (confirm with `nvidia-smi --version`)

## Symptoms

- iDRAC Lifecycle Log shows event `OEM.1.0.GPUFault` with severity Critical
- DCGM reports `GPU has fallen off the bus` / `GPU_XIDDB_79`
- `nvidia-smi` returns `Not Found` for the affected GPU UUID
- Kernel log contains `NVRM: Xid (PCI:<bus>): 79, pid='<unknown>'`

## Root cause

Common causes include:

1. PCIe lane signal integrity issue (loose or damaged cable/riser)
2. GPU firmware crash leading to PCI Express link loss
3. Power delivery transient on the GPU power rail
4. Overheating causing the GPU to assert a fatal error

## Remediation steps

### Step 1 — Cordon and drain affected node

```bash
kubectl cordon gpu-server-02
kubectl drain gpu-server-02 --ignore-daemonsets --delete-emptydir-data
```

Ensure all workloads have migrated before proceeding.

### Step 2 — Issue GPU reset via iDRAC

From the iDRAC web UI or racadm:

```bash
racadm jobqueue create --realtime -t GPURESET -r ALL
```

Alternatively, cycle server power via iDRAC to force PCIe re-enumeration.

### Step 3 — Re-run DCGM health check

After power cycle / reset:

```bash
dcgmi health -g 0 -s g
dcgmi diag -r 2
```

Confirm GPU is visible in `nvidia-smi` and all DCGM health checks pass before uncordoning.

## Escalation

If Xid 79 recurs after GPU reset, engage Dell support for PCIe riser inspection or GPU replacement (hardware fault).
