# PSU Redundancy Loss on PowerEdge XE9680 — Detection and Response

> **PLACEHOLDER** — SME: replace body with the real Dell KB article for PSU failure on XE9680.

## Summary

The XE9680 ships with four 2400 W power supplies in a 2+2 redundant configuration. Loss of one PSU degrades redundancy; loss of two PSUs in the same redundancy group risks system shutdown. This article covers detecting the fault, safely acknowledging it, and scheduling physical replacement.

## Affected products

- Dell PowerEdge XE9680 (all GPU configurations)

## Symptoms

- iDRAC Lifecycle Log shows `OEM.1.0.PSULost` with severity Critical
- PSU status LED amber on the rear of the chassis
- iDRAC Dashboard shows PSU in "Absent" or "Failed" state
- System power budget may be exceeded; GPU power capping may activate automatically

## Root cause

Common causes:

1. Loss of PDU feed to that PSU's AC input
2. PSU hardware failure (internal fault)
3. Blown rack circuit breaker for that PSU's branch circuit

## Remediation steps

### Step 1 — Acknowledge PSU fault in iDRAC

Clear the active alert to stop alarm escalation while the physical investigation proceeds:

```bash
racadm clrsel
```

Or via iDRAC UI: Maintenance → System Event Log → Clear.

### Step 2 — Schedule PSU replacement with facilities

1. Confirm which PSU slot is faulted: `racadm getsensorinfo` or iDRAC → Power → PSU status.
2. Check the corresponding PDU branch and rack circuit breaker — restore feed if tripped.
3. If the PSU has failed (not just lost feed), raise a Dell hardware dispatch for hot-swap replacement. XE9680 PSUs are hot-swappable.

### Step 3 — Confirm remaining PSU load within limits

```bash
racadm getsensorinfo | grep -i "psu\|watt"
```

Ensure the three remaining PSUs can carry total system load (GPU + CPU + DRAM). If load exceeds 3× PSU capacity, reduce GPU power limits temporarily:

```bash
nvidia-smi -pl 300 -i all
```

## Escalation

If PDU feed is intact and the PSU still shows failed, request a Dell on-site dispatch for hot-swap replacement. Provide iDRAC Lifecycle Log and `racadm getsensorinfo` output.
