# GPU Thermal Throttle on XE9780L — Detection, Cooling Check, and Resolution

| | |
|---|---|
| **Article ID** | KB001213 |
| **Version** | 4 |
| **Last updated** | 2025-07-22 |
| **Classification** | Break/Fix — Thermal / Cooling |
| **Default severity** | Warning (Sev 3; Sev 2 if sustained > 30 min or multi-GPU) |
| **Audience** | Datacenter operations, facilities |
| **Applies to** | Dell PowerEdge XE9780L, NVIDIA H100 SXM5 80 GB |

## Summary

The H100 SXM5 engages hardware thermal slowdown when GPU temperature crosses the ~85 °C throttle threshold, cutting SM clocks (typically from ~1410 MHz toward 900 MHz or below) to protect the silicon. No data is lost and jobs keep running, but compute throughput drops 20–40% and job ETAs extend accordingly. Thermal throttle is a protective response, not the fault itself — the actionable problem is whatever removed the thermal headroom: facility cooling, rack airflow, a failed fan, or sustained maximum power draw. Sustained operation near the throttle point also accelerates component wear (see HBM error correlation in [KB000456](KB000456.md)), so recurring throttle events should be treated as a capacity/facilities problem, not background noise.

## Affected products

- Dell PowerEdge XE9780L with NVIDIA H100 SXM5 80 GB GPUs
- Most frequently observed in high-density rack rows and during data centre cooling excursions

## Error signature

The canonical signatures for this fault are:

- `thermal throttle`
- `GPU temperature threshold exceeded`

iDRAC Lifecycle Log message IDs: `OEM.1.0.ThermalThrottle`, `GPU.1.0.ThermalThrottled` (severity Warning). `nvidia-smi` reports active clock throttle reason `HW Thermal Slowdown`.

## Symptoms

- iDRAC Lifecycle Log records `OEM.1.0.ThermalThrottle` with severity Warning
- `nvidia-smi -q -d PERFORMANCE` shows `HW Thermal Slowdown: Active`; SM clock well below rated boost
- DCGM reports `GPU temperature threshold exceeded` and reduced compute throughput on the affected GPU
- Training throughput drops 20–40% on affected GPUs; job ETA extends with no errors in application logs
- iDRAC fan zones ramp to or near 100%
- Inlet temperature above the 25 °C target is the usual accompanying finding

## Sample log excerpt

Representative sequence from a production occurrence on `gpu-server-01` — a gradual ramp (5 minutes from nominal to throttle), with the inlet-temperature drift identifying the facility as the driver:

```
15:31:00Z INFO  dcgm[1234]: GPU 3: Temp 71°C, Power 385W (limit 400W) — under ML training workload
15:33:00Z WARN  iDRAC[LifecycleLog]: Thermal: Fan zone 2 at 85% — elevated due to GPU 3 heat load
15:34:30Z WARN  iDRAC[LifecycleLog]: Thermal: Inlet temp 27°C — above nominal (24°C)
15:35:01Z WARN  dcgm[1234]: GPU3: thermal throttle active — temperature 89°C exceeds 85°C threshold
15:35:01Z WARN  dcgm[1234]: GPU temperature threshold exceeded: performance throttled to prevent damage
15:35:01Z WARN  nvidia-smi[1235]: GPU 3: Clock throttle reason: HW Thermal Slowdown — SM clock 1410 MHz → 900 MHz
15:35:02Z WARN  iDRAC[LifecycleLog]: OEM.1.0.ThermalThrottle — GPU 3 thermal throttle active. Temp: 89°C. Threshold: 85°C.
15:35:02Z WARN  dcgm[1234]: GPU 3 compute throughput reduced 35% due to thermal throttle
15:35:05Z WARN  iDRAC[LifecycleLog]: All fans at 100%. Max cooling engaged for GPU 3.
```

Triage hint: a single GPU throttling with normal inlet temperature points at a local cause (fan, heat spreader, that GPU's workload); several GPUs or several nodes throttling together points at the facility (CRAC/CRAH, containment).

## Impact

- **Workload impact:** Jobs on the affected GPU continue running at reduced throughput — expect slower progress and extended ETAs, not job loss or corruption. The temporary power cap applied during remediation lowers throughput further until conditions recover.
- **Service risk:** Low — no drain, reset, or migration is involved. If the cooling check fails (bad fan, facility excursion), a follow-up hardware or facilities action is required, and sustained throttling should be escalated before it degrades hardware.
- **Data risk:** None.
- **Estimated remediation duration:** ~10 minutes for workload reduction and cooling verification; facility-side fixes run on their own timeline.

## Root cause

1. **Elevated inlet air temperature** — CRAC/CRAH unit fault, setpoint drift, or cooling capacity shortfall. The most common cause; visible as inlet temperature above 25 °C in iDRAC before the GPU event.
2. **Rack airflow problems** — hot-aisle containment breach, blanking panels missing, or recirculation raising the effective inlet temperature for upper chassis positions.
3. **Sustained maximum workload** — continuous 400 W per-GPU draw with marginal cooling headroom; the fleet runs correctly at 400 W with inlet ≤ 25 °C, so this cause always co-occurs with one of the above.
4. **Failed or degraded chassis fan** — remaining fans compensate at 100% but cannot hold the affected zone under full load.

## Remediation steps

### Step 1 — Reduce GPU workload to lower temperature (`reduce_workload`)

Cap GPU power to restore thermal headroom immediately (throttling already costs throughput, so an explicit cap loses little and stabilizes clocks):

```bash
nvidia-smi -pl 300 -i <gpu_index>    # reduce from 400 W to 300 W
```

Monitor recovery:

```bash
watch -n 2 nvidia-smi --query-gpu=index,temperature.gpu,clocks.sm,clocks_throttle_reasons.hw_thermal_slowdown --format=csv
```

Expect the temperature to fall below 80 °C within a few minutes and `HW Thermal Slowdown` to clear (`Not Active`). If the temperature does not respond to a 100 W power reduction, suspect a heat-spreader/cold-plate contact problem and escalate.

### Step 2 — Verify fan speeds and inlet temperature via iDRAC (`check_cooling`)

Find and fix the reason the headroom disappeared:

1. **Inlet temperature** (target ≤ 25 °C): `racadm getsensorinfo | grep -i inlet`. If above target, notify facilities — check CRAC/CRAH status and setpoints for the affected row, and check whether neighbouring nodes show the same drift.
2. **Fan health**: `racadm getsensorinfo | grep -i fan`. All fans should report `Present`/`OK` with plausible RPM. A failed fan is hot-swappable — replace immediately; do not run full GPU load with a fan down.
3. **Airflow**: physically inspect the rack for hot-aisle containment gaps, missing blanking panels, or obstructions at the chassis intake/exhaust.

### Step 3 — Confirm GPU temperature below threshold after cooling (`verify_temps`)

Once the underlying cause is addressed:

```bash
nvidia-smi --query-gpu=index,temperature.gpu,clocks_throttle_reasons.hw_thermal_slowdown --format=csv,noheader
```

All GPUs should read below 80 °C with throttle reason `Not Active`. Restore the full power limit and confirm the node holds it:

```bash
nvidia-smi -pl 400 -i <gpu_index>
```

Monitor for 10 minutes at full workload. Stable temperatures ≤ 84 °C with no throttle events closes the incident; a return to throttle at full power means the root cause is not resolved — repeat Step 2 or escalate.

## Escalation

- Inlet ≤ 25 °C, all fans healthy, but throttle persists at rated power → suspect degraded thermal interface (heat spreader / liquid-cooling loop on liquid-assisted configurations). Open a Dell service case for thermal inspection; include iDRAC thermal sensor history and DCGM temperature telemetry.
- Multiple nodes throttling in the same row → escalate to facilities as a cooling-capacity incident; consider proactive fleet-wide power caps until resolved.
- Recurring throttle on the same GPU across weeks → track against that GPU's ECC error history ([KB000456](KB000456.md)) and flag for closer monitoring.
