# GPU HBM Uncorrectable ECC Error (DBE) — Detection and Remediation

> **PLACEHOLDER** — SME: replace body with the real Dell KB article for HBM ECC DBE on XE9680 / H100 SXM5.

## Summary

A double-bit ECC error (DBE) on the GPU's High Bandwidth Memory (HBM) is uncorrectable by hardware. Unlike single-bit errors (SBE), a DBE cannot be fixed in-flight — it indicates physical memory corruption and the GPU must be drained and reset. If DBEs persist, the GPU should be retired.

## Affected products

- Dell PowerEdge XE9680 with NVIDIA H100 SXM5 80 GB GPUs (HBM3 memory)

## Symptoms

- iDRAC Lifecycle Log shows `OEM.1.0.MemUCE` with severity Critical
- DCGM metric `DCGM_FI_DEV_ECC_DBE_VOL_TOTAL` exceeds 0
- Kernel log: `NVRM: GPU-...: ECC DBE (double-bit error) in HBM at row <addr>, bank <n>`
- Application memory errors or SIGBUS in GPU workloads

## Root cause

HBM DBEs are typically caused by:

1. Aging or defective HBM memory cells
2. Cosmic ray / soft error (rare; usually a single occurrence)
3. Operating at extreme temperatures accelerating cell degradation

A single isolated DBE may be a soft error; recurring DBEs indicate hardware failure.

## Remediation steps

### Step 1 — Cordon and drain affected node

```bash
kubectl cordon gpu-server-01
kubectl drain gpu-server-01 --ignore-daemonsets --delete-emptydir-data
```

### Step 2 — Reset GPU ECC counters and clear fault

```bash
nvidia-smi --gpu-reset -i <gpu_index>
nvidia-smi --ecc-config=1 -i <gpu_index>  # ensure ECC re-enabled post-reset
```

Or via iDRAC if driver-level reset is unavailable.

### Step 3 — Re-run DCGM ECC diagnostic

```bash
dcgmi diag -r 3 -j ecc
dcgmi health -g 0 -s m  # memory health
```

If `DCGM_FI_DEV_ECC_DBE_VOL_TOTAL` remains 0 after workload restart, return to service. If DBEs recur, retire the GPU.

## Escalation

Persistent DBEs require GPU replacement. Open a Dell hardware support case with the DCGM diagnostic output attached.
