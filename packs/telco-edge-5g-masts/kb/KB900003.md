# eCPRI Fronthaul Link Failure: SFP RX Power Low and Cell Down

| | |
|---|---|
| **Article ID** | KB900003 |
| **Version** | 3 |
| **Last updated** | 2026-04-08 |
| **Classification** | Critical — Fronthaul Transport / Optical |
| **Default severity** | Critical (Sev 1 — full cell outage) |
| **Audience** | RAN field engineers, transport/fiber engineering, network operations center (NOC) |
| **Applies to** | eCPRI-based fronthaul between Ericsson Baseband 6630 and AIR 3268 radios, SFP/SFP+ optical interfaces |

## Summary

eCPRI (enhanced Common Public Radio Interface) carries all traffic between the baseband and the radio unit over a point-to-point or switched optical fronthaul link, replacing legacy CPRI's fixed-rate architecture with an Ethernet-based, more efficient one. The link depends entirely on the optical budget between the SFP transceivers at each end holding within spec — the receiver's RX power must stay within its rated range for the signal to be recovered reliably. Forward Error Correction (FEC) can compensate for a marginal signal for a period, correcting a rising rate of bit errors as RX power degrades, but once RX power drops low enough that FEC's correction capacity is exhausted, the link fails outright. Because eCPRI carries all fronthaul traffic — not just a portion — a link failure takes the entire cell out of service immediately; there is no degraded-but-functional state analogous to TX power derating on a thermal fault. This makes early detection of a degrading (not yet failed) link the highest-value intervention: the FEC correction rate climbing is a warning that precedes the hard failure by minutes to hours depending on how fast the underlying optical fault is progressing.

## Affected products

- Ericsson Baseband 6630 and AIR 3268 fronthaul optical interfaces (eCPRI)
- SFP/SFP+ optical transceivers on both baseband and radio ends of the fronthaul fiber run

## Error signature

The canonical signatures for this fault are:

- `eCPRI link failure`
- `SFP RX power low`
- `fronthaul link down`

Fronthaul optical link log:

```
WARN  fh[gnb-site-05]: SFP RX power trending down — fronthaul link to gnb-site-05, -18.2 dBm (nominal -8 to -12 dBm)
CRIT  fh[gnb-site-05]: eCPRI link failure — SFP RX power low, fronthaul link down, cell down
```

## Symptoms

- SFP RX power trends downward over a period of minutes to hours before the hard failure — rarely an instantaneous drop, which gives a genuine detection window
- FEC correction rate elevated well before the link actually fails — the system successfully compensating for a degrading signal, visible in monitoring before any user-facing impact
- Once RX power drops far enough, FEC correction capacity is exhausted and uncorrectable errors appear, immediately followed by the link declaring down
- The affected cell transitions to OUT_OF_SERVICE with no fronthaul connectivity — this is a hard, binary state, not a degraded-capacity condition
- Neighboring sites and cells on independent fronthaul runs are unaffected — confirms the fault is localized to this specific optical path, not a shared upstream transport issue

## Sample log excerpt

Representative sequence from `gnb-site-05` (Suburban Stealth Pole):

```
09:15:00Z INFO  fh[gnb-site-05]: eCPRI link active — baseband to AIR 3268, SFP RX -9.4 dBm, TX 0.0 dBm nominal
11:47:22Z WARN  fh[gnb-site-05]: SFP RX power trending down — fronthaul link to gnb-site-05, -13.6 dBm (nominal -8 to -12 dBm)
11:47:22Z WARN  fh[gnb-site-05]: FEC correction rate elevated — marginal optical budget, possible connector contamination
12:19:41Z WARN  fh[gnb-site-05]: SFP RX power trending down — fronthaul link to gnb-site-05, -18.2 dBm (nominal -8 to -12 dBm)
12:19:41Z WARN  fh[gnb-site-05]: FEC exhausted — uncorrectable errors detected on eCPRI link
12:20:15Z CRIT  fh[gnb-site-05]: eCPRI link failure — SFP RX power low, fronthaul link down, cell down
12:20:15Z CRIT  bb[gnb-site-05]: Cell gnb-site-05/cell-1 — service state OUT_OF_SERVICE, no fronthaul connectivity
```

The RX power decline from -9.4 dBm to -18.2 dBm over roughly 3 hours, with the FEC correction-rate warning logged 33 minutes before the actual link failure, is the pattern worth acting on proactively — a link that's degrading this steadily and this predictably rarely self-corrects, and catching it at the first FEC warning avoids the outage the current event ended in.

## Impact

- **Workload impact:** The affected cell is completely out of service — no coverage or capacity from this specific cell — for the duration of the fault, since eCPRI carries all fronthaul traffic between baseband and radio with no partial-service fallback.
- **Service risk:** High. A fully down cell creates a coverage gap for users in its footprint; they fall back to neighboring cells if in range and capacity allows, or lose service entirely if this cell's footprint isn't adequately overlapped. This is categorically different from a degraded-capacity condition (e.g. thermal TX derating) — the cell is not available at all, not available-but-reduced.
- **Estimated remediation duration:** ~10 minutes if a protection-path switch or optical port reset resolves it. Physical fiber fault location and repair (a damaged or contaminated connector, a fiber bend, a degraded splice) can take from hours to longer depending on the nature and location of the fault along the run.

## Root cause

In observed order of frequency, per standard optical link troubleshooting:

1. **Connector contamination** — dust or debris on the fiber connector face at either end progressively blocks optical transmission; the classic marginal-degradation-before-failure pattern, and the most common single cause of this exact symptom sequence.
2. **Fiber bend or physical stress** — excessive bend radius or physical stress on the fiber run (common at cable entry points, service loops, or where fiber wasn't properly secured) introduces attenuation that can worsen with temperature or vibration over time.
3. **SFP transceiver degradation** — the optical transceiver itself aging or degrading independent of the fiber path; distinguishable by swapping the SFP module and checking whether RX power recovers with a known-good unit.
4. **Fiber splice or connector degradation over time** — a splice or connector that was marginal at installation continuing to degrade, sometimes accelerated by thermal cycling at an outdoor site.

## Remediation steps

### Step 1 — Switch fronthaul traffic to protection fiber path, if provisioned (`switch_protection_path`)

Fastest path to restoring the cell, if available — attempt before any physical diagnosis:

```
Transport management system: initiate protection-path switchover for gnb-site-05 fronthaul
Confirm cell transitions back to IN_SERVICE on the protection path
```

If no protection path is provisioned at this site, proceed directly to Step 2 with elevated urgency since the cell remains fully down until resolved.

### Step 2 — Reset the SFP optical port at both baseband and radio ends (`reset_optical_port`)

```
Baseband OSS: reset the fronthaul SFP port at the baseband end
Physically reseat or reset the corresponding SFP at the AIR 3268 radio end
Confirm link re-establishment attempt and monitor initial RX power reading
```

A reset resolves a transient issue but will not fix a physically degraded fiber connector or fiber run — if RX power returns to the same degraded level immediately after reset, this confirms the fault is physical, not a soft/transient issue, and Step 4 dispatch should proceed without delay.

### Step 3 — Verify SFP RX power returns to nominal range (`verify_rx_levels`)

```
Confirm RX power reading is back within nominal range (-8 to -12 dBm for this link class) after Step 1 or Step 2
Confirm FEC correction rate has returned to baseline (near zero), not just that the link is technically up — a link that's up but still showing an elevated FEC rate is still degrading and will likely fail again
```

### Step 4 — Dispatch fiber crew to inspect and clean/repair the fronthaul fiber run (`dispatch_fiber_crew`)

```
Dispatch with the RX power trend and FEC correction history from this event to focus the inspection
On-site checklist: connector cleaning (both ends), fiber run physical inspection for bend/stress points, SFP swap test if connector cleaning doesn't restore nominal RX power
Do not close the ticket on a temporary reset-driven recovery (Step 2) alone if the underlying physical cause hasn't been identified and corrected — the same degradation pattern will very likely recur
```

## Escalation

- No protection path is provisioned and the reset in Step 2 does not restore the link → escalate to NOC as an active full-cell outage requiring expedited fiber crew dispatch, not routine scheduling.
- RX power returns to nominal after cleaning but degrades again within days → escalate to transport engineering for a fuller fiber-run inspection; recurring degradation this fast points at an ongoing physical stress issue (bend, thermal cycling at a bad splice) rather than a one-off contamination event.
- SFP swap test does not resolve a persistently low RX power reading with a confirmed-clean, confirmed-unstressed fiber path → escalate to Ericsson field service for baseband/radio optical interface hardware diagnosis.
