# GPU Out of Memory: CUDA OOM on NVIDIA RTX in Dell Precision Laptops

> **PLACEHOLDER** — SME: replace with real Dell / NVIDIA guidance for OOM on mobile RTX Ada GPUs.

## Summary

A CUDA Out of Memory (OOM) error occurs when a GPU compute workload requests more VRAM than is available on the device. Mobile RTX Ada Generation GPUs (RTX 5000 Ada: 16 GB, RTX 4000 Ada: 12 GB) have less VRAM than their desktop counterparts, making OOM more common when running large AI model training or inference jobs.

## Affected products

- Dell Precision 7780 / 7680 / 5680 with NVIDIA RTX Ada Generation mobile GPUs
- PyTorch ≥ 2.0, TensorFlow ≥ 2.12 under Windows 11 or Ubuntu 22.04

## Symptoms

- `torch.cuda.OutOfMemoryError: CUDA out of memory. Tried to allocate X GiB` in application output
- `nvidia-smi` shows GPU memory at or near 100% utilisation before the crash
- Application exits with `RuntimeError: CUDA error: device-side assert triggered`
- Subsequent CUDA calls in the same process fail with `CUDA error: invalid device function`

## Root cause

1. **Model too large for VRAM** — LLM or vision model weights exceed available VRAM
2. **Memory fragmentation** — repeated allocations/frees leaving unusable VRAM holes
3. **Shared memory with display** — display compositor consuming VRAM alongside the compute workload
4. **Missing gradient checkpointing** — storing all activations without recomputation strategy

## Remediation steps

### Step 1 — Identify GPU processes

```bash
nvidia-smi --query-compute-apps=pid,name,used_memory --format=csv
```

Identify the highest VRAM consumer.

### Step 2 — Terminate GPU process

```bash
# Linux
kill -9 <pid>

# Windows (PowerShell)
Stop-Process -Id <pid> -Force
```

### Step 3 — Verify VRAM freed

```bash
nvidia-smi --query-gpu=memory.used,memory.free --format=csv
```

Confirm memory.free has recovered to near the GPU's total VRAM.

### Step 4 — Advise workload adjustment

For the application owner:

- Reduce `batch_size` (halving batch size roughly halves activation memory)
- Enable gradient checkpointing in PyTorch: `model.gradient_checkpointing_enable()`
- Use 8-bit or 4-bit quantisation (via `bitsandbytes` library) for inference
- Move embedding layers to CPU with `accelerate` device_map="auto"

## Escalation

If OOM persists after workload tuning, consider migrating training jobs to a node with more VRAM (RTX 6000 Ada: 48 GB) or to a cloud GPU instance.
