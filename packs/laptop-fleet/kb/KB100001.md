# Display Driver TDR: NVIDIA nvlddmkm Timeout on Dell Precision Laptops

> **PLACEHOLDER** — SME: replace with the real Dell KB article for TDR on Precision 7000/5000 series with RTX Ada / Ampere GPUs.

## Summary

A TDR (Timeout Detection and Recovery) event occurs when Windows detects that the GPU has stopped responding for more than 2 seconds (default). Windows attempts to reset the display driver; if successful, you see Event ID 4101 in System Event Log (`nvlddmkm stopped responding and has successfully recovered`). If recovery fails, the system blue-screens with `VIDEO_TDR_FAILURE`.

## Affected products

- Dell Precision 7780, 7680, 5680 with NVIDIA RTX 5000 / 4000 Ada Generation
- Dell Precision 7770, 7670 with NVIDIA RTX 5000A / 4000A Ampere
- NVIDIA driver 526.x – 546.x on Windows 11

## Symptoms

- Windows Event Log: Event ID 4101, Source nvlddmkm, Level Error
- `C:\Windows\Minidump\` contains a new minidump file following the event
- CUDA applications crash with `CUDA error: an illegal memory access was encountered` or `device-side assert triggered`
- Display briefly goes black and returns (< 30 seconds)

## Root cause

Common TDR triggers on Precision laptops:

1. **Driver regression** — older or pre-release driver versions with known shader compiler bugs
2. **Power limit conflicts** — battery mode reducing GPU TDP causing scheduler timeout under heavy CUDA load
3. **Overclocking/memory OC** — aggressive GPU Boost clocks exceeding stability margin
4. **Thermal throttle cascade** — GPU thermal limit causing a clock reduction that the OS scheduler interprets as a hang
5. **DX12/Vulkan API misuse** — application-level GPU hang from bad synchronisation primitive usage

## Remediation steps

### Step 1 — Collect TDR minidump

```powershell
Copy-Item "C:\Windows\Minidump\*.dmp" -Destination "$env:USERPROFILE\Desktop\TDR-dumps"
```

Send to NVIDIA/Dell support if the issue recurs.

### Step 2 — Update GPU driver

Download the latest Studio Driver from MyDell or NVIDIA:

```powershell
# Check current driver
nvidia-smi --query-gpu=driver_version --format=csv,noheader
```

Install via Dell Update or NVIDIA GeForce Experience. Prefer **Studio Drivers** for compute workloads.

### Step 3 — Increase TDR delay (workaround)

If TDR is triggered only under long CUDA kernels (> 2 s):

```powershell
# Run as Administrator
Set-ItemProperty -Path "HKLM:\System\CurrentControlSet\Control\GraphicsDrivers" `
  -Name "TdrDelay" -Value 8 -Type DWord
Restart-Computer
```

**Note:** This masks the symptom; root cause should still be investigated.

### Step 4 — Verify stability

After driver update and reboot:

```powershell
# Run CUDA stress test (requires CUDA toolkit)
nvbandwidthtest --testcase 14 --numLoops 100
```

## Escalation

If TDR persists after driver update and TdrDelay increase, submit a Dell Support Request with the minidump and `nvidia-bug-report.log` output.
